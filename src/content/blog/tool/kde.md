# 起因

因为在 [X.Org](https://www.x.org/wiki) 时期我还在用台式，
那时候觉得纯键盘驱动的窗口管理器操作效率好像更高一点，
当然也抱有觉得好玩和装逼的心态就玩了一段时间的窗口管理器。
所以到了 [Wayland](https://wayland.freedesktop.org) 时期一开始用的也是窗口管理器，
最开始是 [Sway](https://swaywm.org)。

发现 Sway 发布周期长，输入法补丁合进主分支了也得等挺久才会发布，
又懒得从 [AUR](https://aur.archlinux.org/packages/sway-git) 构建。
听说 [Hyprland](https://hypr.land) 的输入法支持不错，于是迁移过去了。

之后……就一直用着了，也没觉得有什么特别坏的地方，只是 Hyprland 默认的窗口管理逻辑不是很丰富，
我个人也不是很在意动画的类型，所以就一直觉得……「也许该换了？」

但最终也没有什么特别的动力去迁移，不过那个时候其实就感觉到自己其实并不适合平铺式纯键盘驱动的窗口管理逻辑。
我并没有驾驭这种逻辑的能力，也没有一套好的键位方案思路，自己瞎配一套快捷键其实效率其实是非常低的，
毕竟我对窗口管理的需求并没有总结提炼，只是觉得「应该要有这些功能」配好一套基础的键位就没动了。

开始用笔记本电脑后问题逐渐凸显，小屏幕、触控板、小键盘……我逐渐觉得我的窗口管理方案不足以支撑了，
而且我发现我喜欢最大化一个窗口占住全屏，专注地在一个窗口里工作，Hyprland 对此的支持是较差的。

然后我又看到了 [niri](https://niri-wm.github.io/niri)，但最后我就只是试了一下就放弃，
一方面是当时其实我是想试试其他窗口管理器能不能修复 ThinkBook G7+ 的触控板在用了一会儿后
多指操作会失灵的问题（当然最后我发现这不是窗口管理器的问题）。
还有一方面就是它依赖 `xdg-desktop-portal-gnome`，虽然官方也给出了不使用 `nautilus` 的方法，
但是我不想干预软件包依赖关系。

然后……其实一开始我想的是单独使用 KWin 作为窗口管理器然后再捣鼓一番，
最后还是干脆使用 [KDE](https://kde.org) 了。

# 优点

- 良好的触控板支持

  极大地提升了笔记本窗口管理的体验，我的窗口调度能力显著提升。

- 默认高刷

  不知道是不是我的问题，但 Hyprland 和 Sway 默认都使用 60Hz
  而 KDE 默认会使用 120Hz，打 osu! 体验显著提升。

- Plasma Shell 良好集成

  稍微调整一下就能获得极好的体验，以前写的一些小脚本工具也能接着用。
  并且 `pinentry-qt`、`pkexec` 等工具集成更好。

- 剪贴板支持

  虽然二维码快速分享剪贴板这个功能有点……但是我挺爱用的。
